# Project Guidelines

## Project purpose

This project is a static GitHub Pages audio demo for a BMCI-MINT speech dereverberation paper. It contains:

- A main audio example browser (`index.html`, `src/app.js`).
- A subjective listening evaluation page (`subjective.html`, `src/subjective.js`).
- Local WAV examples and a generated `audio-manifest.json`.

## Development environment

- Use PowerShell-compatible commands on Windows unless there is a clear reason to use Bash.
- Preview locally with:

```powershell
python -m http.server 8000
```

- Open pages through `http://localhost:8000/`, not `file://`, so `fetch('./audio-manifest.json')` works.

## Publishing

- The public GitHub Pages site is published from the `gh-pages` branch.
- Push only to `gh-pages` for website updates unless the user explicitly asks otherwise.
- Do not force-push.
- After pushing, remind the user that GitHub Pages may take a few minutes to redeploy and that `Ctrl + F5` may be needed.

## Audio manifest

- `audio-manifest.json` is generated by `scripts/generate-manifest.mjs`.
- If any `.wav` files are added, removed, moved, or renamed, run:

```powershell
node scripts/generate-manifest.mjs
```

- Do not hand-edit generated manifest entries unless absolutely necessary.

## Main demo UI conventions

- Main UI logic lives in `src/app.js`.
- Method display names should use paper-style notation:
  - `MINT-ℓp (p=1.0)`
  - `MINT-Eℓp (p=1.0)`
  - `MINT-Reference`
  - `WPE`
  - `GWPE`
- Keep WPE/GWPE grouped between input references and BMCI-MINT branches.
- Keep noisy and spectral-subtraction branches labeled as `noisy input` and `spectral-subtraction input` where branch labels are shown.

## Subjective listening page conventions

- Subjective page logic lives in `src/subjective.js`.
- The subjective page is for listeners, not organizers.
- It should not expose aggregation/average summaries to listeners.
- It should not show raw file paths or filenames in the audio cards.
- It should not include unprocessed examples or noisy-input branches unless the user explicitly asks.
- It currently evaluates only the spectral-subtraction branch with SNR 30/20/10/5 dB and default `lambda = 0.1` for 5 dB.
- The page supports English and Chinese; keep all user-facing subjective-page text covered by the translation table in `src/subjective.js`.
- All examples should begin unrated. Do not default missing scores to 3.
- Missing/unrated scores should be exported/submitted as `null`.
- The Submit button must block Formspree submission until all examples have been scored.
- If scores are incomplete, show a localized error message and scroll to the first unrated example.
- Keep the integer 1–5 score buttons visible, and keep the `+0.5` / `−0.5` half-point control to their right.
- The current score should be displayed between the 1–5 buttons and the half-point control.
- The active Formspree endpoint is:

```text
https://formspree.io/f/mpqgvpvo
```

- Submit behavior should POST results to Formspree only after all examples are rated, and download a backup JSON only if submission fails.

## Style conventions

- Keep the page simple and listener-friendly.
- Avoid dense explanatory text in the subjective page.
- Keep the scoring guidance panel sticky at the top of the subjective page.
- Keep the SNR selector in the scoring guidance header unless the user asks to move/remove it.
- Keep title sizing consistent with the current global `h1` rule.

## Validation

Before reporting a UI/script change as complete, run:

```powershell
node --check src/app.js
node --check src/subjective.js
```

If manifest-related logic changes, also validate that the subjective page mappings still resolve to existing manifest entries.
